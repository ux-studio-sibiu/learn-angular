Lesson 10

Change detection, zone.js, OnPush & zoneless

Change detection is how Angular gets from "data changed" to "DOM updated". It's the biggest conceptual difference from React, and the one that matters most once animation loops are involved.

What triggers an updateWhat gets re-checked
Reactyou call setStatethat component and its children re-run, then diff

1. The animation trap: 60 checks per second

zone.js patches every async browser API. After each one finishes, it tells Angular "something might have changed", and Angular checks the app. A requestAnimationFrame loop is an async callback 60 times a second. Start the canvas inside the zone and watch the meter.

App render passes: …

@switch (zoneMode()) { @case ('inside') { } @case ('outside') { } }
  • The baseline of a few passes per second comes from the three card timers in section 2.
  • Inside the zone the ball looks identical, but Angular re-checks the whole app every frame. On a heavy editorial page, that's dropped frames.
  • The fix is one line in the canvas (bouncing-canvas.ts): ngZone.runOutsideAngular(() => requestAnimationFrame(tick)). Every rAF scheduled from there stays outside too. GSAP tickers, Three.js render loops, scroll and pointer-move listeners all belong there.
  • Need to update the UI from outside? Set a signal (only its readers get checked), or wrap the call in ngZone.run().

2. OnPush: skip what didn't change

Each card has a timer that adds 1 to seconds every second, and flashes when Angular re-renders its template. Click the unrelated button, run the loop inside the zone above, and compare.

  • Default: re-checked on every pass anywhere in the app: each unrelated click, each frame of the inside-zone loop.
  • OnPush + plain field: the timer runs, but the view stays frozen. Nothing told Angular this component changed. Click inside it and the real number appears (its own event marks it dirty). That's the bug people hit when they add OnPush to old code.
  • OnPush + signal: updates once a second and ignores everything else. seconds.set() marks exactly this component. That's the combination to use by default.
  • In ng serve (dev mode) Angular runs an extra verification pass that re-evaluates Default components, which is why the Default card's count climbs about twice as fast as the meter. Production builds skip it.

3. What marks an OnPush component for checking

  • An input got a new value (by reference: mutating an object doesn't count, lesson 03).
  • An event in its own template, or in a child's.
  • A signal its template reads changed.
  • The async pipe received a value (the pre-signals way).
  • Someone called inject(ChangeDetectorRef).markForCheck(): the manual escape hatch you'll see in older OnPush code.

4. Zoneless: the end state

Replace provideZoneChangeDetection() with provideZonelessChangeDetection() in app.config.ts and remove zone.js from the polyfills. Then the list above is the only way anything updates: no more "check everything after every event", no runOutsideAngular needed, about 11 kB less JavaScript.

  • It's stable in v20 and the default from v21. WEF's current nav still loads zone.js, so this is a real decision for their rebuild.
  • What breaks: plain fields changed from timers, fetch callbacks or third-party callbacks (the middle card's bug, everywhere). Signals + OnPush everywhere first, zoneless after. This site isn't switched yet, since lessons 01–02 deliberately use plain fields.
  • Also good to know: ExpressionChangedAfterItHasBeenCheckedError (NG0100) is dev mode's verification pass catching a binding that changed during a check, usually state set in ngAfterViewInit. Fix the data flow rather than silencing it.
