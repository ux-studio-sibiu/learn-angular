GSAP inside Angular

GSAP is where choreography lives: timelines, staggers, scroll-driven scenes. Integrating it is the recipe from lessons 09–12, packed into one helper, useGsap() in services/gsap.ts: start in the browser after render, outside the zone, inside a gsap.context(), reverted on destroy.

1. A timeline with SplitText

Shaping the future, one frame at a time

A timeline: characters rise in with a stagger, then the subtitle, then the shapes pop from the centre.

0%
… render passes per second
  • The timeline is built once in useGsap(). The buttons only call play(), reverse(), progress() on it, the way you'd keep a timeline in a ref in React.
  • The progress readout and slider are updated in onUpdate by writing to the DOM directly (loop strategy A). A signal there would mean 60 state updates per second.
  • The pitfall: clicks run inside Angular's zone. GSAP's ticker sleeps when nothing is animating; a tween started from a click wakes it inside the zone, and every frame triggers change detection. Compare the meter after "Restart" and after "Restart inside the zone". The fix is wrapping handler calls in runOutsideAngular (useOutsideZone()), or going zoneless.
  • SplitText injects its own <div>s, which don't get Angular's scoped style attributes, so they're styled with ::ng-deep. A rare legitimate use.

2. ScrollTrigger: a pinned, scrubbed scroll story

Scroll down. The stage pins while 1800 px of scrolling drives a timeline. Per-frame progress goes into a CSS variable (the bar at the bottom); only the chapter number is a signal, so this OnPush component re-renders 3 times per scroll, not 60 times per second.

Scroll ↓
  • ScrollTrigger is created inside the same gsap.context(), so navigating away kills it and removes the pin spacer. A ScrollTrigger left behind would keep measuring a page that no longer exists.
  • Plugins are registered once, in the browser (gsap.registerPlugin in afterNextRender). On the server the component simply renders its HTML.
  • With reduced motion, useGsap re-runs setup with reduced: true: no pin, no scrub, all chapters visible as a plain list.

3. GSAP in Angular's enter/leave hooks

Lesson 13's function form, now with GSAP: (animate.enter)="gsapEnter($event)" and (animate.leave)="gsapLeave($event)". Angular keeps the leaving item in the DOM until GSAP's onComplete calls animationComplete().

This is the cleanest way to put GSAP on things Angular creates and destroys (list items, modals, route content): Angular owns when, GSAP owns how.

The rules, in one list

  1. Create animations in afterNextRender (browser only, DOM ready).
  2. Run them outside the zone, including tweens started from event handlers.
  3. Scope them with gsap.context(fn, hostElement) and revert() on destroy.
  4. Per-frame values go to the DOM / CSS variables; only meaningful changes become signals.
  5. Read reduced motion from one place and rebuild when it changes.
  6. Let Angular decide when elements exist (@if, @for), and use the enter/leave hooks for GSAP on those.
