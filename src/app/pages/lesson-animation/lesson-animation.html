Angular-native animation

Before reaching for GSAP: most UI motion is CSS, triggered by Angular bindings. Angular adds two things CSS can't do alone: animating elements out before they're removed, and morphing between two DOM states with View Transitions.

Every demo reads MotionPreference (lesson 05). Set it to "reduce" there and everything here turns instant.

1. CSS first: bindings toggle classes, CSS animates

This panel animates its height with grid-template-rows: 0fr → 1fr, no JavaScript measuring. The element is always in the DOM (it's a class, not an @if), so CSS can transition both ways.

This covers hovers, toggles, accordions and micro-interactions: Angular only flips the class. The limit: with @if, the element is removed immediately, so there's nothing left to animate out.

2. animate.enter & animate.leave

animate.enter="toast-in" adds that class when the element is created. animate.leave="toast-out" adds the class when it's about to be removed, and Angular waits for the CSS animation to finish before removing it from the DOM.

  • Works with @if, @for, @switch and routing, anywhere Angular adds or removes elements. That's the AnimatePresence problem, solved in the template.
  • The class form is enough most of the time. The function form (animate.leave)="fn($event)" is the bridge to JS libraries: animate $event.target, then call $event.animationComplete().
  • On the server they do nothing, and with reduced motion (CSS animation: none) Angular sees no animation and removes the element straight away.

3. View Transitions: morph between two layouts

Each tile has a view-transition-name. When the layout changes inside document.startViewTransition(), the browser photographs the old and new positions and animates each tile between them. Reordering and layout changes for free, with no measuring code.

Give an element the same view-transition-name on two pages and it morphs across the navigation (a list thumbnail growing into a detail hero).
  • Browser support is good in Chromium and Safari; elsewhere the update just happens without animation.

The old way: @angular/animations

You'll see trigger(), state(), transition('void => *', [animate(300)]) and [@fade] bindings in older code. That package is deprecated since v20.2 in favour of animate.enter/leave + CSS, and it's not installed here. Knowing it exists matters when reading WEF's existing Angular code; new code shouldn't use it.

Which tool, when

  1. CSS + class bindings: hovers, toggles, accordions, micro-interactions.
  2. animate.enter / leave: things appearing and disappearing (toasts, modals, list items, route content).
  3. View Transitions: layout changes, reordering, page-to-page continuity.
  4. GSAP (lesson 14): choreographed timelines, scroll-driven storytelling, precise sequencing.
  5. Three.js (lesson 15): only when it's genuinely 3D.

Each step down costs more JavaScript, more code and more accessibility work. "Use the cheapest tool that achieves the creative intent" is the answer the WEF job description is looking for.
