How components talk to each other. Same rule as React: data goes down (inputs ≈ props), events go up (outputs ≈ callback props), and markup can be passed in as content (ng-content ≈ children).

1. Content projection (children & slots)

The card doesn't take a title string or a body config. The parent writes the markup, and the card decides where each piece goes. That's composition over configuration, the same approach as your React components.

Different from React: projected content is created by the parent, always, even if the child never shows it. Wrapping <ng-content /> in an @if hides it but doesn't stop it from being created. For "render only when needed" you pass an <ng-template> instead (≈ a render prop). That comes up later.

2. input() & output()

Each chip receives a label and emits remove. It doesn't touch the list: the parent owns the data and decides what removing means.

  • Inputs are signals: the child reads this.label(), and can build a computed from it (≈ deriving from props).
  • Inputs are read-only inside the child. Writing to one is a compile error, same as mutating props in React.
  • Outputs aren't DOM events: they don't bubble. Only the direct parent can listen.
  • Name outputs after what happened (remove, select), without an on prefix.

3. model() & two-way binding

The stepper edits a value that the parent owns. [(value)], the "banana in a box", is shorthand for [value]="guests()" (valueChange)="guests.set($event)".

Guests Parent: {{ guests() }} × 40 CHF = {{ total() }} CHF

The data still has one owner (the parent's guests signal). model() just saves you writing the input + output pair, which is what React does with value + onChange. In MVC terms, it's model binding for a component.
