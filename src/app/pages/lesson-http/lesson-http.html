1. Resolver: load before the page shows

This route has resolve: { talks: talksResolver }. The router waited for the request, then created this page with the data as an input. Did you notice the ~0.7 s pause when you clicked the nav link? That's the trade-off: no loading spinner, but navigation feels slower.

Like useQuery, it gives you value(), isLoading(), error() and reload() as signals, with no useEffect + three useStates. Unlike TanStack Query there's no shared cache between components. In v20 it's marked experimental, but it's the direction Angular is going.

Call the service, subscribe, copy the result into signals. This is what most existing Angular code looks like (often with RxJS operators like map, switchMap, catchError in between).

Observables vs Promises, in short

  • Lazy: http.get() sends nothing until you subscribe. A fetch() starts immediately.
  • Cancellable: unsubscribing aborts the request. That's what httpResource and switchMap do when the input changes, and it's why there are no race conditions when clicking fast.
  • Many values: an Observable can emit many times (websockets, progress events). HTTP emits once and completes.
  • toSignal(observable$) turns an Observable into a signal, and unsubscribes when the component is destroyed.
  • On a server-rendered site (lesson 12), data fetched on the server is embedded in the HTML and reused in the browser (the HTTP transfer cache), so it isn't fetched twice.
