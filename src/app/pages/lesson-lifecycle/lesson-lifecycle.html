Lesson 09

Lifecycle & the DOM

Most of the time Angular owns the DOM and you just bind to it. Libraries like GSAP, Three.js, charts or maps need the real element, at the right moment, and must be torn down when the component goes away. This lesson is that moment, and that teardown.

  • Inputs aren't set in the constructor, so label() is still the default there. Use ngOnInit, an effect, or a computed to work with input values.
  • ngOnChanges and the effect both see input changes. In new code, prefer computed / effect on the input signal.

3. Wrapping a DOM library: create, run, destroy

The canvas is a stand-in for GSAP or Three.js: it grabs its element with viewChild, starts a requestAnimationFrame loop and a ResizeObserver in afterNextRender, and stops both in DestroyRef.onDestroy. It also reads MotionPreference from lesson 05, so "reduce" there freezes the ball.

@if (showCanvas()) { }

Tick forget cleanup, then unmount and remount a few times: the counter keeps climbing. Each "gone" canvas is still animating in memory, invisible, eating CPU. That's the classic SPA leak (in React it's the missing useEffect cleanup, in jQuery a plugin never destroyed). With GSAP it means ScrollTriggers firing for elements that no longer exist; with Three.js, GPU memory that never comes back.

The recipe for lessons 14–16

  1. viewChild.required('el') for the container or canvas.
  2. afterNextRender(() => …) to create the library instance (browser only, DOM ready).
  3. inject(DestroyRef).onDestroy(() => …) to kill timelines, observers, loops, renderers.
  4. Lesson 10 adds the last piece: run the loop outside Angular's zone, so 60 frames a second don't trigger 60 change detection passes.
