Three.js inside Angular

No wrapper library here: Angular has no react-three-fiber equivalent in wide use, so you write the integration yourself. It's the same recipe as the canvas (lesson 09) and GSAP (lesson 14), plus one new concern: GPU memory, which JavaScript's garbage collector doesn't free for you.

How it fits together

  • Inputs drive the scene, not the other way round. Colour and detail are plain Angular inputs. Inside the component, effects apply them to the existing material and geometry, so nothing is rebuilt. That's the react-three-fiber idea ("props in, objects updated") written by hand.
  • The loop never touches Angular. setAnimationLoop and the pointer listener are registered outside the zone. Rotation and pointer tilt are plain variables. Stats leave the loop twice a second through an output (loop strategy B), and that's the only change detection the scene causes.
  • It pauses itself. An IntersectionObserver stops the loop when the canvas is off-screen (scroll down and fps drops to nothing), and the browser already pauses rAF in background tabs.
  • Reduced motion → render on demand. No loop at all; the scene renders once per change (a colour click, a pointer move). Toggle "reduce" in lesson 05 and come back.
  • Pixel ratio is capped at 2. A 3× phone screen would otherwise render 9× the pixels of a 1× screen, for no visible gain.

Disposal: the part the garbage collector can't do

Geometries, materials, textures and the WebGL context itself live on the GPU. Removing the component from the DOM frees the JavaScript objects, not the GPU memory. Tick forget dispose and mount/unmount repeatedly: "live WebGL renderers" keeps climbing. Around 16, the browser logs "Too many active WebGL contexts" and starts killing the oldest one, which on a real page might be your hero.

Proper cleanup (in DestroyRef.onDestroy): stop the loop, disconnect observers, remove listeners, geometry.dispose(), material.dispose(), every texture.dispose(), renderer.dispose(), renderer.forceContextLoss(). Same for swaps: changing the detail level disposes the old geometry before using the new one.

For a real 3D hero

  • Assets: GLTF models compressed with Draco or Meshopt, textures as KTX2. Load them with GLTFLoader inside afterNextRender; show the poster until they're ready.
  • Fallbacks: the @placeholder poster doubles as the no-WebGL and reduced-data version, and it's what the server renders (lesson 12), so search engines and slow phones get a real image.
  • Accessibility: the canvas has role="img" and a label; any information shown in 3D needs an HTML equivalent next to it.
