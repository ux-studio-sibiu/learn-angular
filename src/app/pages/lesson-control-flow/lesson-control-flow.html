Control flow: @if, @for, @switch

Blocks that add, repeat or swap parts of the template. They read like Razor's @if / @foreach, but they are reactive: when the data changes, Angular adds or removes the DOM for you.

1. @if, @else if, @else

The element is removed from the DOM when false (like React), not hidden with CSS (like .hide()). For CSS hiding use [hidden]="!x" or a class.

@if (user; as u) {

Welcome back, {{ u.name }} ({{ u.role }}).

} @else {

Nobody is signed in.

}

2. @switch

Pick one branch by value. Handy for loading / error / ready states, or for mapping CMS block types to components.

@for (s of statuses; track s) { }

@switch (status) { @case ('loading') {
Loading…
} @case ('error') {
Something went wrong.
} @case ('done') {
Loaded 3 talks.
} @default {
Waiting to start.
} }

3. @for, track & @empty

track is required, and it plays the same role as React's key: it tells Angular which DOM row belongs to which item. Like a few talks, then shuffle and compare the two lists.

track t.id ✔

    @for (t of talks; track t.id; let i = $index, first = $first) {
  • {{ i + 1 }}{{ t.title }}
    • } @empty {
  • No talks. Add one.
    • }

track $index ✘

    @for (t of talks; track $index) {
  • {{ $index + 1 }}{{ t.title }}
    • } @empty {
  • No talks.
    • }

With track t.id the like counts move with their talk: Angular moves the existing DOM rows. With track $index the rows stay put and only the text changes, so the likes now sit on the wrong talk. It's the same bug as key={index} in React, and it's the reason track exists. Index is fine for static lists that never reorder.

You'll still see the old syntax

Before Angular 17 these were structural directives: *ngIf="user as u; else none", *ngFor="let t of talks; trackBy: byId", [ngSwitch]. Existing codebases (probably WEF's too) are full of them. They work the same way, but need imports: [NgIf, NgFor], and trackBy was optional, which is why so many lists re-rendered more than needed.
