2. Lazy loading (this site was just migrated)

Until this lesson, app.routes.ts imported every page at the top, so every page was in the main bundle, even ones you never visit. Now each lesson is loadComponent: () => import(…), and this lesson's routes are a separate file loaded with loadChildren.

  • Run ng build and compare: the main chunk shrank, and each lesson is a "Lazy chunk file". Open DevTools → Network, click a lesson, and watch its chunk arrive.
  • Next.js does this automatically per page. Angular only splits where you use loadComponent / loadChildren (or @defer, lesson 11). A static import anywhere pulls the code back into the main bundle.
  • The roadmap stays eager: it's the landing page, so lazy-loading it would only add a request.

3. Router features switched on in app.config.ts

  • withComponentInputBinding(): route params, query params and route data arrive as component inputs (used above).
  • withViewTransitions(): route changes use the browser's View Transitions API, so pages cross-fade. It's a first look at lesson 13: it can be styled with CSS (::view-transition-old/new).

Not covered here: resolvers (load data before the route activates) come with HTTP in lesson 07, and canDeactivate ("you have unsaved changes") with forms in lesson 08.
